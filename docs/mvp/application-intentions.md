I am a staff software engineer who loves to cook.

I'd like to create an application that will help me discover new recipes, convert those recipes into a shopping list, easily cross off things from the shopping list that I already have in my fridge or pantry, and then I can take that list to the store and make sure that I don't forget any ingredients for the things I want to cook for that week.

Help me build out an application, PRD, for such an application. It needs to have recipe discovery from free or open source recipe sources on the internet and be able to convert them into a format that can be used within the application or it should be able to support custom recipe entry for my own recipes that I can store within the application.

Every week on a Saturday or Sunday I'll go through my list of recipes and determine what I want to cook for that week and check off the recipes that I'd like to cook. By doing so it should automatically add those ingredients to my cart. If I remove a recipe it should remove those items from my cart. If multiple recipes use the same ingredient they should combine together within the cart so that I know how much of
each ingredient total to buy for all the recipes I need for that week.

Then I can check items off of my grocery list/cart when I'm at the store and putting things into my cart.

Please see ~/Documents/git/scaffolding to see how I like to set up my applications, unless I have a good reason to make them otherwise. I like nextjs PWA applications that are designed with mobile-first in mind, mongodb, shadcn components, tailwind, etc.

Help me construct a PRD which will represent all of the features and details that this application will need to have when it is fully featured and fully functional. this PRD should be a markdown file which will live in the repo as a sibling to this file.

Help me also brainstorm app names for this application.

I'd like this to be FOSS so that anyone could contribute. My intention is to release with an MIT license.
