# PRD acceptance traceability

This matrix is the repeatable evidence index for the 18 acceptance criteria in
[the PRD](prd.md#24-acceptance-criteria). A criterion is considered covered
when the referenced automated checks exercise its product boundary or when the
listed manual check is run against the documented local setup. Test names are
kept in the test files so the matrix does not become a second, drifting test
specification.

## Evidence commands

Run the full automated evidence set from a clean local test setup:

```sh
npm run prettify
npm run ci
```

The integration suite requires a MongoDB replica set and a database name that
contains `test` or `ci`. Authenticated browser checks run when
`E2E_USER_EMAIL` and `E2E_USER_PASSWORD` are provisioned in the ignored local
environment; tests that require optional public recipe fixtures or hosted
policy configuration explain their skip condition in the test output.

For focused evidence, use the command in the rightmost column after the
environment prerequisites are available.

## Coverage boundaries

The matrix deliberately distinguishes evidence types. Unit and integration
tests prove contracts and persistence invariants; browser tests prove user
journeys and responsive behavior; the manual checks cover installation and
two-browser collaboration where the local CI account setup is intentionally
environment-specific. A skipped browser test is not release evidence: its
required environment must be provisioned and the test rerun before claiming
that criterion as browser-verified.
